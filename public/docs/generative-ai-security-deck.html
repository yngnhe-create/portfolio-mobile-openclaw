3. 데이터는 어디로 가는가?

같은 “사내 채팅창”이라도 뒤에서 외부 모델 API를 부르면 데이터는 외부로 갈 수 있습니다.

4

4. Web형 vs 기업형(API) vs 설치형

Web형

  • 가장 쉽고 빠름
  • 구축 필요 없음
  • 데이터 외부 전송 가능성 큼
보안성 낮음

기업형(API)

  • 우리 채팅 UI / 인증 / 로그 통제 가능
  • 실제 모델은 외부일 수 있음
  • 겉은 내부, 두뇌는 외부
보안성 중간

설치형

  • 모델을 우리 서버에 설치
  • 외부 API 없이 운영 가능
  • 가장 강한 통제 가능
보안성 매우 높음
중요: “기업형 UI”라고 해서 자동으로 안전한 건 아닙니다. 실제 모델 호출이 외부 공급자로 가는지 반드시 확인해야 합니다.

5. 인프라 위치와 모델 위치는 다르다

축 1. 인프라 위치

  • 온프레미스: 우리 서버실, 우리 데이터센터
  • 퍼블릭 클라우드: AWS, Azure, GCP, Naver Cloud 등

축 2. 모델 위치

  • 외부 공급자 모델: OpenAI, Anthropic 등
  • 우리가 설치한 모델: Qwen, EXAONE, DeepSeek 등

우리 앱(온프렘/클라우드)외부 공급자기업형 API
우리 퍼블릭 클라우드우리 설치 모델클라우드 self-host
우리 온프레미스우리 설치 모델완전 자체형

6. 가장 중요한 보안 비교표

케이스 데이터 외부 유출 가능성 학습에 쓰일 가능성 외부에서 우리 데이터 볼 가능성 통제 수준
Web형 SaaS 높음 정책에 따라 가능 상대적으로 높음 낮음
기업형 UI + 외부 API 중간~높음 정책/계약 따라 다름 공급자 접근 가능성 존재 중간
우리 퍼블릭 클라우드 + 자체 모델 낮음~중간 우리가 안 하면 없음 우리 운영자/클라우드 관리자 높음
우리 온프레미스 + 자체 모델 가장 낮음 우리가 안 하면 없음 우리 내부 관리자 매우 높음
전용 프라이빗/폐쇄형 공급자 낮음 계약으로 제한 가능 제한적 높음~매우 높음

7. 사람들이 가장 많이 헷갈리는 질문

Q1. “학습에 안 쓰이면 안전한 거 아닌가요?”

아니요. 학습에 안 써도 저장, 로그, 운영자 접근, 법적 요청 대응 같은 리스크는 남습니다.

Q2. “우리 채팅창이면 내부 AI 아닌가요?”

아닙니다. 뒤에서 외부 모델 API를 호출하면 데이터는 외부로 갈 수 있습니다.

Q3. “온프레미스면 무조건 안전한가요?”

아닙니다. 내부 관리자 권한, 로그 저장, 문서 권한, 네트워크 분리까지 제대로 설계해야 합니다.

Q4. “퍼블릭 클라우드는 다 위험한가요?”

그것도 아닙니다. 우리 계정의 폐쇄형 self-host 구조는 상당히 강한 통제가 가능합니다.
