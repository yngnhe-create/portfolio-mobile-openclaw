# 생성형 AI 보안 1페이지 요약

## 1. 생성형 AI는 무엇인가?
생성형 AI는 사람처럼 문장을 만들고, 요약하고, 답변하고, 코드를 작성하는 AI입니다. 핵심 엔진은 보통 **LLM(대규모 언어모델)** 입니다.

대표 예시:
- ChatGPT
- Claude
- Gemini
- EXAONE
- HyperCLOVA X
- Qwen / DeepSeek / GLM 같은 오픈모델

---

## 2. 제공 방식은 3가지
### ① Web형
사용자가 외부 웹사이트에 직접 접속해 사용하는 방식
- 예: ChatGPT 웹, Claude 웹
- 가장 쉽지만 데이터가 외부로 갈 가능성이 큼

### ② 기업형(API)
회사 내부 채팅창/업무시스템을 만들고, 뒤에서 외부 AI API를 호출하는 방식
- 겉으로는 내부 시스템처럼 보이지만 모델은 외부 클라우드일 수 있음
- 인증/권한/로그는 내부 통제가 가능

### ③ 설치형(온프레미스)
모델을 우리 GPU 서버에 설치하는 방식
- 외부 API 호출 없이 내부에서 처리 가능
- 보안은 가장 강하게 가져갈 수 있음
- 대신 비용/운영 난이도가 높음

---

## 3. 보안은 무엇이 핵심인가?
생성형 AI 보안의 핵심은 아래 3가지입니다.

1. **우리 데이터가 외부로 가는가?**
2. **저장되거나 학습에 쓰이는가?**
3. **외부 공급자나 제3자가 볼 수 있는가?**

즉, AI의 성능보다 먼저 **데이터 흐름과 통제권**을 봐야 합니다.

---

## 4. 방식별 보안 수준
| 방식 | 설명 | 보안성 |
|---|---|---|
| Web형 SaaS | 외부 웹에 직접 입력 | 낮음 |
| 기업형 UI + 외부 모델 API | UI는 내부, 모델은 외부 | 중간 |
| 우리 퍼블릭 클라우드 + 자체 모델 | 외부 클라우드지만 우리 전용 환경 | 높음 |
| 우리 온프레미스 + 자체 모델 | 우리 서버 안에서만 동작 | 매우 높음 |
| 전용 프라이빗형 공급자 | 공급자 모델이지만 폐쇄형 환경 | 높음~매우 높음 |

---

## 5. 쉬운 이해
### Web형
편하지만 가장 조심해야 함

### 기업형 API
겉은 내부 시스템이어도, 두뇌는 외부에 있을 수 있음

### 온프레미스
가장 안전하게 설계할 수 있지만, 가장 직접 운영해야 함

---

## 6. 권고안
### 비민감 업무
- 기업형 API 활용 가능

### 사내 문서/업무 보조
- 기업형 API 또는 private deployment 권장

### 금융/법무/인사/연구기밀
- 전용 프라이빗 또는 온프레미스 우선

### 최고 보안 요구
- 온프레미스 self-host
- 폐쇄망 + 접근권한 + 감사로그 필수

---

## 7. 경영진 메시지
> 생성형 AI 보안은 “이 AI가 좋으냐”보다, **우리 정보가 어디로 가고, 누가 보고, 누가 통제하느냐**를 결정하는 문제입니다.
