# 기업 AI 도입 완전 가이드

부제: 모델, 인프라, 제공 방식, 보안, 중국계 최신 모델, 활용 케이스를 한 번에 이해하는 문서형 가이드

---

## 1. 먼저 이해해야 할 핵심: 모델과 인프라는 다른 것

### 1-1. 모델 = AI의 두뇌
질문에 답하고, 글을 쓰고, 코드를 만들고, 이미지를 이해하는 **AI 자체**를 뜻한다.

예시:
- GPT-5.4
- Claude Sonnet 4.6
- Gemini 2.5 Pro
- Qwen
- Kimi
- DeepSeek

### 1-2. 인프라 = AI가 돌아가는 장소
그 AI를 **어디서 실행하느냐**를 뜻한다.

예시:
- 온프레미스(우리 회사 서버)
- 우리 회사가 쓰는 클라우드
- 격리된 기업용 클라우드
- 공급사 서버

### 1-3. 한 줄 비유
- **모델** = 엔진
- **인프라** = 엔진을 올려놓고 돌리는 차고/공장/건물

모델과 인프라를 섞어서 생각하면 전체 구조가 헷갈리기 쉽다.

---

## 2. 모델은 크게 두 부류로 보면 쉽다

### 2-1. 직접 설치 가능한 모델
모델 파일을 받아서 우리 서버나 우리 클라우드에 설치할 수 있는 모델이다.

예시:
- Qwen
- DeepSeek 일부
- Llama 계열

특징:
- 우리가 직접 운영 가능
- 데이터 통제력이 높음
- 대신 GPU, 운영 인력, 배포 역량이 필요함

### 2-2. 서비스형 모델
공급사가 운영하는 AI 서비스를 연결해서 쓰는 모델이다.

예시:
- GPT-5.4
- Claude Sonnet 4.6
- Gemini 2.5 Pro
- Kimi

특징:
- 직접 설치하지 않음
- 계약을 하면 공급사가 **API 키**를 줌
- 우리 시스템은 그 키를 사용해 공급사 AI 서비스에 연결함

### 2-3. API 키를 쉽게 설명하면
API 키는 비전문가 기준으로 보면 **시리얼 넘버**, **라이선스 키**, **출입 카드** 같은 개념이다.

즉:
1. 공급사와 계약한다
2. 사용용 키(API 키)를 받는다
3. 우리 시스템이 그 키를 넣고 공급사 서버에 연결한다
4. 질문을 보내고 답을 받는다

---

## 3. 공급사는 보통 어떤 방식으로 제공하나?

### 3-1. 웹 서비스
브라우저로 바로 접속해서 쓴다.

예시:
- ChatGPT
- Claude
- Gemini
- Kimi

장점:
- 가장 쉬움
- 가장 빠르게 시작 가능

단점:
- 회사 통제가 약할 수 있음
- 기밀정보 입력 위험이 큼

### 3-2. 연결형 서비스
계약 후 API 키를 받아 우리 시스템에 연결해서 쓴다.

예시:
- OpenAI
- Anthropic
- Google
- Moonshot

장점:
- 사내 포털, 사내 서비스에 붙이기 좋음
- 로그, 승인, 권한통제 설계 가능

단점:
- 모델 자체는 외부에서 돌아감
- 질문 내용은 외부 처리 시 전달됨

### 3-3. 직접 설치형
모델 파일을 받아 우리 서버나 우리 클라우드에 직접 설치한다.

예시:
- Qwen
- DeepSeek 일부
- Llama 계열

장점:
- 통제력 최강
- 외부 반출 최소화 가능

단점:
- 운영 부담이 큼
- 최신 최고 성능 모델은 직접 운영이 쉽지 않을 수 있음

---

## 4. 실제 케이스는 4개로 보면 된다

---

## 케이스 A. 우리 안에서 직접 돌림

### 정의
AI도 내부, 데이터도 내부.

### 구조
- 모델: 내부 설치형
- 인프라: 우리 서버 / 우리 클라우드
- 저장: 내부

### 쉽게 말하면
회사가 AI 기계를 직접 들여와서 회사 안에서 돌리는 방식.

### 무엇이 저장되나
- 원문 문서
- 대화 로그
- 업무 데이터
- 결과물
- 캐시와 운영 로그

모두 내부에 저장 가능하다.

### 장점
- 데이터 통제력 최고
- 외부 반출 최소화 가능
- 폐쇄망/규제 환경에 유리
- 공급자 종속이 낮음

### 단점
- GPU와 운영 인력 필요
- 구축 난이도 높음
- 최신 최고 성능 모델은 직접 운영이 어려울 수 있음

### 적합한 곳
- 금융
- 의료
- 국방
- 반도체/제조 핵심 IP
- 외부 반출 금지 환경

### 한 줄 요약
**보안 최우선이면 A가 가장 강하다.**

---

## 케이스 B. 외부 전용 금고에서 돌림

### 정의
밖에 있지만 기업용으로 격리·통제가 강한 환경에서 쓰는 방식.

### 구조
- 모델: 서비스형 모델
- 인프라: 격리 클라우드
- 저장: 격리 클라우드 쪽에 남을 수 있음

### 쉽게 말하면
일반 외부 서비스가 아니라, 보안이 강한 **전용 외부 금고** 안에서 AI를 쓰는 방식.

### 대표 예시
- Azure OpenAI
- AWS Bedrock
- GCP Vertex AI

### 무엇이 저장되나
- 프롬프트
- 응답
- 로그
- 캐시 일부
- 감사 로그

이런 것들이 격리된 클라우드 환경에 남을 수 있다.

### 장점
- 최신 상용 모델 사용 가능
- 리전, IAM, 감사로그, 네트워크 통제 가능
- 기업 보안팀이 설명하기 쉬움
- 성능과 통제의 균형이 좋음

### 단점
- 저장 위치는 여전히 외부 클라우드
- 클라우드 종속 존재
- 비용 관리 필요

### 적합한 곳
- 대기업
- 클라우드 보안 체계를 이미 쓰는 회사
- 빠르게 강력한 모델을 도입하려는 조직

### 한 줄 요약
**보안과 성능의 균형형 표준 선택**

---

## 케이스 C. AI는 밖에서 쓰고 기록은 안에 둠

### 정의
AI 답변은 외부 서비스에서 받고, 기록과 로그는 우리 시스템에 남기는 방식.

### 구조
- 모델: 서비스형 모델
- 인프라: 공급사 서버에서 추론
- 저장: 우리 서버 / 우리 DB 중심

### 쉽게 말하면
외부 전문가에게 자문은 받지만, 회의록과 업무 기록은 회사 내부 캐비닛에 보관하는 방식.

### 무엇이 저장되나
내부 저장:
- 대화 기록
- 업무 로그
- 사용자 이력
- 결과물
- 사내 포털 사용 이력

외부 처리 시 전달되는 것:
- 질문 본문
- 일부 문맥
- 추론에 필요한 입력 데이터

즉,
- **처리는 외부**
- **기록은 내부**

### 장점
- 빠르게 도입 가능
- 사내 포털/사내 시스템 중심 운영 가능
- 기록과 감사는 내부에서 관리 가능
- 최신 외부 모델 성능 활용 가능

### 단점
- 질문 자체는 외부 AI가 읽음
- 정책/계약 검토 필요
- 민감정보는 마스킹/통제가 필요함

### 적합한 곳
- 사내 포털 기반 AI 도우미
- 보고서 초안 생성
- 회의록 요약
- 문서 검색 + 답변 생성
- 대기업의 현실적 도입 방식

### 한 줄 요약
**외부 AI 성능은 쓰되, 회사 기록은 내부에 남기고 싶은 경우**

---

## 케이스 D. 웹에서 그냥 씀

### 정의
브라우저에서 개인/일반 플랜으로 바로 쓰는 방식.

### 구조
- 모델: 서비스형 모델
- 인프라: 공급사 서버
- 저장: 외부 서비스에 남을 수 있음

### 쉽게 말하면
개인 메신저나 일반 웹툴로 회사 일을 처리하는 것과 비슷한 느낌.

### 무엇이 저장되나
- 대화 내용
- 사용 이력
- 일부 서비스 개선용 데이터
- 계정 활동 로그

### 장점
- 가장 쉬움
- 무료 또는 저렴함
- 바로 시작 가능

### 단점
- 기업 기밀 입력 위험
- 감사/통제 약함
- 정책 확인 없이 쓰면 위험

### 적합한 곳
- 테스트
- 개인 생산성
- 비기밀 초안 작업

### 한 줄 요약
**가장 쉽지만 기업 핵심업무용으로는 비추천**

## 5. 4개 케이스를 한 줄로 비교하면

| 케이스 | 처리 위치 | 저장 위치 | 가장 쉬운 설명 |
|---|---|---|---|
| A | 내부 | 내부 | 우리 안에서 직접 돌림 |
| B | 외부(격리 클라우드) | 외부(격리 클라우드) | 외부 전용 금고에서 돌림 |
| C | 외부 | 내부 | AI는 밖에서 쓰고 기록은 안에 둠 |
| D | 외부 | 외부 가능성 큼 | 웹에서 그냥 씀 |

## 6. 보안을 판단하는 4가지 핵심 질문

### 6-1. 내 데이터로 AI가 학습하나?
- 내 입력이 모델 개선에 쓰이는가?
- 정책상 금지인지, 계약상 금지인지 구분 필요

### 6-2. 데이터는 어디에 저장되나?
- 우리 서버?
- 외부 클라우드?
- 공급사 서버?
- 리전 선택 가능한가?

### 6-3. 공급자가 내용을 볼 수 있나?
- 기술적으로 가능한가?
- 정책상/운영상 얼마나 막고 있나?

### 6-4. 못 보게 막는 장치는 있나?
- 암호화
- IAM
- 감사 로그
- 삭제 정책
- 계약 조항

## 7. 각 케이스별 보안 관점 핵심

### A. 우리 안에서 직접 돌림
- 공급자 열람: 사실상 불가
- 학습: 구조상 없음
- 저장: 내부
- 설명: 가장 강함

### B. 외부 전용 금고에서 돌림
- 공급자 열람: 클라우드 운영사 이론상 가능
- 학습: 계약상 없음
- 저장: 격리 클라우드
- 설명: 통제 장치가 강한 외부 환경

### C. AI는 밖에서 쓰고 기록은 안에 둠
- 공급자 열람: 질문 본문 처리 시 외부에서 읽음
- 학습: 정책/계약으로 막을 수 있음
- 저장: 내부 로그/DB 중심
- 설명: 저장 위치 기준으론 내부 지향적

### D. 웹에서 그냥 씀
- 공급자 열람: 가능성 높음
- 학습: 설정 확인 필요
- 저장: 외부 서비스
- 설명: 가장 조심해야 함

## 8. 중국계 최신 모델 공급 방식 정리

### Qwen (Alibaba)
제공 방식:
- 웹: Qwen Chat
- 연결형 서비스: Alibaba Cloud Model Studio API
- 직접 설치형: 오픈웨이트 직접 배포 가능

특징:
- 웹, API, 온프레미스까지 폭넓게 지원
- 중국 모델 중 공급 방식이 가장 다양함

### Kimi (Moonshot AI)
제공 방식:
- 웹: Kimi Chat
- 연결형 서비스: Moonshot API
- 전용 환경: 일부 기업 대상 협의 가능

특징:
- 기본은 호스팅형 웹/API 중심
- 긴 문맥 처리 강점

### DeepSeek / GLM 계열
제공 방식:
- 직접 설치형: 자체 서버 설치 가능
- 클라우드 설치형: AWS/Azure/GCP VM 배포 가능
- 관리형 API: 서드파티 통해 사용 가능

특징:
- 오픈모델/서드파티 배포 활용이 현실적
- 비용 효율과 자체 운영 유연성이 장점

## 9. 모델 성향 간단 비교

### GPT-5.4
- 범용성 강함
- 생태계 넓음
- 문서/코딩/멀티모달 전반 강함

### Claude Sonnet 4.6
- 문서·긴 글·요약·계약서 해석 강점
- 지시 따르기와 글쓰기 안정적

### Gemini 2.5 Pro
- Google 생태계 연동 강함
- 장문 컨텍스트, 멀티미디어 처리 강점

### Qwen 3 계열
- 오픈모델 + API 병행 가능
- 직접 설치와 외부 연결 둘 다 검토하기 좋음

### Kimi K2.5
- 긴 문맥·호스팅형 활용에 강점
- 문서 처리와 빠른 PoC에 적합

### DeepSeek / GLM 계열
- 온프레미스/프라이빗 배포 현실성 높음
- 비용 효율형 자체 운영에 유리

## 10. 어떤 회사에 어떤 케이스가 맞나

### A가 맞는 회사
- 외부 반출 금지
- 최고 보안
- 규제 산업
- 자체 인프라 운영 가능

### B가 맞는 회사
- 최신 모델 성능 필요
- 기업 보안 체계 중요
- 클라우드 인프라 친화적

### C가 맞는 회사
- 빠르게 도입하고 싶음
- 사내 포털/사내 DB 중심
- 외부 AI 성능을 쓰되 기록은 내부에 두고 싶음

### D가 맞는 회사
- 테스트
- 개인 실험
- 비기밀 업무

## 11. 최종 한 장 요약

### 가장 쉬운 결론
- **보안 최우선** → A. 우리 안에서 직접 돌림
- **보안과 성능 균형** → B. 외부 전용 금고에서 돌림
- **현실적인 빠른 도입** → C. AI는 밖에서 쓰고 기록은 안에 둠
- **간편하지만 위험** → D. 웹에서 그냥 씀

### 가장 중요한 원칙
AI 보안은 단순히 “어느 모델을 쓰냐”보다 아래가 더 중요하다.

1. 어디서 처리되나?
2. 무엇이 어디 저장되나?
3. 누가 볼 수 있나?
4. 학습에 쓰이나?
5. 계약과 로그 통제가 있나?

### 진짜 핵심 한 줄
**모델과 인프라를 분리해서 보고, 그 다음 처리 위치와 저장 위치를 같이 봐야 한다.**
